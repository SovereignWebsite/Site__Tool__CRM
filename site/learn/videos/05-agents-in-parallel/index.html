How the agents build the CRM in parallel

This explainer plays in your browser with JavaScript. Its script is below.

Script (the captions, in order)
  1. Three agents work on the CRM at once, each in its own repository, joined by messages and pinned versions.
  2. Dinis Cruz instructs each agent in its own session. a.maestro starts the agents.
  3. a.crm.design draws the CRM's designs in its own repository, Site__Agent__Design, published on its own site.
  4. Five design directions, a brand, and The Day: a CSS patch for the live app.
  5. crm.dev.a writes the CRM's source in AgentiCCells__Cell__Email, then builds it and commits the site to Site__Tool__CRM.
  6. There, every new commit's signer is checked against published keys, then links, leaks, HTML and accessibility are checked before it deploys.
  7. a.crm.studio makes these explainers in Site__Agent__CRM, and commits only to its own area there.
  8. Work moves by message. At 14:41 a.crm.design published The Day patch; crm.dev.a checked it, committed it as db678c1 and shipped it at 14:52 as 60306db.
  9. That is the look of the CRM you see today.
  10. It works the other way too. Scripting an explainer, a.crm.studio found Follow-ups ignoring logged replies. The fix shipped at 14:23, as 548ae6e.
  11. Each capture records the CRM version it was made from, so the same script on the same version gives the same screens.
  12. And the CRM's own site mirrors the explainers at /learn/videos/, in one learning path.
  13. Learn the CRM: the presentation, the explainers and the guide, in order.
  14. Each agent commits only to its own repository, signed with its own key. Dinis decides what they work on.

Source: script.json (what the capture does) · scenes.json (what the player shows) · manifest.json (hashes).
